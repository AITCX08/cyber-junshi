# README 效果演示设计

## 目标

把 README 中偏工具流程说明的案例改成面向访客的“效果演示”：让用户先看到自己会怎样提问，再直接读到赛博军师会给出的完整回答，快速理解产品输出的判断风格和可执行性。

## 范围

- `README.md` 增加或替换为 `## 效果演示`，包含三条中文问答。
- `README.en.md` 保留语义等价的英文效果演示，作为现有国际化例外。
- `tests/test_public_artifacts.py` 调整 README 契约，验证三条问答主题、停止条件和记忆隐私说明仍然存在。
- 不改变 MCP 服务、知识库、Skill、SQLite 或工具接口。

## 呈现结构

每条效果演示使用与 `RongZheng-skill` 相同的阅读结构：

```markdown
### 问：用户的完整问题

赛博军师  ❯ 一段完整回答
```

回答不展示工具名、JSON、内部推理过程或多轮追问。工具能力通过自然语言体现：区分事实和猜测、比较可逆选择、给出可直接使用的消息、说明观察窗口和停止条件。

## 三条效果演示

1. **连续取消见面**：用户询问对象 A 两次临时取消后是否继续约。回答不把取消等同于动机或人格判断；建议只发送一次非指控式澄清消息、观察 48 小时，未回复则停止追问。
2. **关系冷淡后的边界沟通**：用户因对方回复变少而想连发消息。回答帮助用户把“回复变少”与“对方不在乎”分开；建议一次明确表达需求，并把沉默、拒绝或边界请求作为停止信号。
3. **分开后是否联系**：用户想以“问候”为由重新联系已明确提出空间需求的前任。回答说明问候不应绕过已说出的边界；建议先停止联系、把注意力放回自己的支持系统，只有对方主动恢复沟通时才考虑回应。

## 文案边界

- 章节标题仅为“效果演示”，不在每条案例附近额外标记其数据来源或生成方式。
- 不声称成功率，不诊断人格、动机或心理状态。
- 不提供操控、跟踪、绕过拉黑、冒充、第三方施压或反复联系的建议。
- 每条回答必须有一个清晰、尊重边界的下一步和停止条件。
- 已有 README 的全局隐私与仓库案例说明继续保留；本次不新增单独免责声明。

更新文档测试以要求中英文 README 都包含 `效果演示` / `Effect examples`、三条主题、一次消息、48 小时、未回复停止，以及 `remember_question` 与 `recall_subject` 的显式和对象隔离语义。运行定向测试、完整测试、Ruff 和 `cyber-junshi audit-knowledge`。
