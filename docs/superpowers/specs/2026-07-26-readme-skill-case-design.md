# README Skill 工作流案例设计

## 目标

在两个 README 中加入一段真实感足够、但完全虚构的完整案例，让新用户理解关系 Skill、11 个 MCP 工具、本地知识和显式对象记忆如何协同工作。

## 文档语言规则

仓库 Markdown 默认使用中文。当前唯一明确的国际化例外是 `README.en.md`，它保留与中文默认 README 对应的英文版本；除此之外，新增或修改的说明文档、Skill 和案例均使用中文。

## 范围

中文默认 README 新增 `真实 Skill 工作流案例`；`README.en.md` 增加对应英文版本。案例使用中性别名“对象 A”，情境为两次取消见面。

案例展示六个阶段：

1. 用户问题，以及宿主 Agent 选择关系 Skill。
2. `assess_safety` 返回普通安全路由。
3. `search_knowledge` 返回证据等级与来源标识。
4. 用 `structure_case` 分开事实、推断和未知。
5. 比较三个方案，选出一个有 48 小时观察窗口、降级和停止信号的行动方案。
6. 给出一条自愿、非指控式消息；只有用户明确同意后才调用 `remember_question`，之后通过 `recall_subject` 展示按对象隔离的连续记忆。

## 非目标与安全规则

- 案例是虚构合成，不是真实聊天、咨询记录，也不保证关系结果。
- 不诊断任何人，也不从取消见面直接推断动机。
- 不暗示 MCP 服务会自动写入记忆。
- 只给出一次尊重边界的澄清消息；未回复是停止条件。
- 不出现真实个人信息、密钥、数据库路径或完整生产对话记录。

## 呈现方式

使用简短的 Markdown 对话块和紧凑的工具结果摘录。结构化内容要足以复现流程，但不为每个工具粘贴完整 JSON。结尾明确区分“宿主 Agent 负责什么”和“赛博军师负责什么”。

## 验证

扩展 `tests/test_public_artifacts.py`，要求中英文 README 均包含案例标题、六个关键工具名、虚构数据声明和显式记忆说明。运行定向测试、完整测试、Ruff 和 `cyber-junshi audit-knowledge`。
